Seal your context files. Break the seal, break the build.

Every coding agent reads a context file. Nobody updates it. skillfile writes yours from the repo and stamps it with a hash — and the moment the repo moves on, CI stops the merge.

Six inputs go in. The manifest, Makefile targets, the README's first paragraph, your structure, tooling markers, and the git log. Nothing is guessed and no model is involved, so the same repo always produces the same bytes.

Three commands, nothing else to learn

skillfile init

Scan, then write both conventions from one source. Refuses to overwrite a file you wrote by hand.

skillfile update

Re-scan, rewrite, reseal. Sub-second and free — there is no model to pay for.

skillfile check

Exit non-zero when the seal no longer matches. In CI it blocks the merge that broke it.

A floor, not a ceiling

skillfile will not capture your architecture philosophy or the reasons behind your conventions — keep writing those by hand, which is exactly why it refuses to touch a hand-written file. It also won't guess: a repo that declares no commands renders "no scripts declared", because an invented command an agent then runs is worse than silence.
