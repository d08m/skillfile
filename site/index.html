Your agent context file is already stale.

Every coding agent reads a context file — and every context file rots the moment nobody remembers to update it by hand. skillfile generates AGENTS.md and Claude-format SKILL.md from your repo, deterministically, and fails your CI when they drift. No LLM calls. No API key. No config.

$ npx skillfile init

The mechanism

Treat context like a lockfile, not documentation.

A stale lockfile fails your build. A stale AGENTS.md just quietly lies to every agent that reads it — wrong commands, dead directories, decisions from three months ago.

skillfile writes a content hash of what it saw into SKILLFILE.md. When your scripts, dependencies, structure, or activity change, check exits non-zero and your CI goes red — the same contract you already trust for lockfiles.

Three commands, nothing else
skillfile init

Scan the repo. Write AGENTS.md (read natively by Cursor, Codex, Copilot, Gemini CLI, 20+ tools) and .claude/skills/…/SKILL.md for Claude — same content, both conventions, one source. Refuses to overwrite a hand-written file.

skillfile update

Re-scan and rewrite. Deterministic, sub-second, free — there is no model in the loop, so there is nothing to pay for and nothing to hallucinate.

skillfile check

Exit non-zero if the repo drifted since generation. Wire it into CI and a stale context file blocks the merge that made it stale.

CI in four lines

The file that keeps itself honest.

# .github/workflows/ci.yml
- run: npm install
- run: npm test
# stale AGENTS.md = red build
- run: npx skillfile check
What it is not

A floor, not a ceiling.

skillfile won't capture your architecture philosophy or the war stories behind your conventions — keep writing those by hand; it refuses to touch a hand-written file for exactly that reason.

What it guarantees is the floor: any agent, any tool, cold session, always knows your real commands, real structure, and real recent activity — and CI proves that stays true.
