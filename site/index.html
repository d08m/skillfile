skillfile reads six things and nothing else. The manifest, Makefile targets, the README's first paragraph, your top-level structure, tooling markers like a CI or test directory, and the git branch and log. It is gitignore-aware, and there is no model in the loop — so the same repo always produces the same bytes.

Three commands, nothing else to learn

skillfile init

Scan, then write both conventions from one source. Refuses to overwrite a file you wrote by hand.

skillfile update

Re-scan and rewrite. Sub-second and free — there is no model to pay for.

skillfile check

Exit non-zero if the repo drifted. In CI, a stale context file blocks the merge that made it stale.

A floor, not a ceiling

skillfile will not capture your architecture philosophy or the reasons behind your conventions — keep writing those by hand, which is why it refuses to touch a hand-written file. It also won't guess: a repo that declares no commands renders "no scripts declared", because an invented command an agent then runs is worse than silence.
